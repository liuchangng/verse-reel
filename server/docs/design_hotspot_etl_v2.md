## 一、根因回顾（§0）

| 热点 | 期望 Top1 | 实际 Top1 | 问题 |
|------|----------|----------|------|
| 古风音乐火了 | 李白《梦游天姥吟留别》 | 释彦悰《三藏法师传序》 | "古风"+"音乐"未命中李白 terms |
| 山水画卷般的秋景 | 王维《山居秋暝》 | 弘历《题张宗苍秋景山水画》 | 检索词含"般的"+限定"山水画" |
| 中秋月圆夜 | 苏轼《水调歌头》 | 石任之《满江红...月饼》 | 当代中秋打油诗 hits=2 排前面 |

核心问题三层：
1. **检索词生成层**：TOPIC_THEME_MAP 覆盖不足 + 停用词未过滤
2. **候选池构建层**：纯倒排 hits 排序，当代高分打油诗靠高频词碾压
3. **term 语义层**：poem_terms 只有原文切词，无主题标签、无金句标记

本次文档聚焦 **第3层**（ETL 工程），A+C 已在 `hotspot.py` 落实现。

## 二、数据现状与问题量化

### 2.1 当前 DB 规模
- `poems`: 2,035,137 首
- `poem_terms`: 28,076,201 行，139,684 个 distinct term
- 平均每首诗 ~14 个 term（标题+正文各切一次）

### 2.2 数据形态实测（v2.1 修订，只读抽样全库）

| 现象 | 实测数据 | 对检索的影响 |

| **同作者同题多篇（组诗拆条/同题集）** | **228,972 个组合，涉及 869,237 行 ≈ 全库 42.7%** | **主矛盾**。杜甫《秋兴八首》拆成 8 条同标题记录（各 64 字，无"其一"后缀）；《江畔独步寻花七绝句》≥7 条。组诗拆条 → 名诗聚合分被摊薄、候选池被同质条目挤占、金句被分散在子条 |

### 2.3 金句粒度实测（v2.1 新增）

倒排 term **是否保留整句取决于 jieba 切分运气**：
- ✅ 命中：`但愿人长久`（8 首）、`床前明月光`（3 首）、`举头望明月`（4 首）——词典中整词化成功
- ❌ 切碎：`明月几时有`（0，切为 明月/几时/有）、`长风破浪会有时`（0）

**结论：金句不能靠"从 jieba term 里识别"，必须由外部金句库按标点断句后整体注入（position='g'），否则不可稳定召回。**

## 三、设计目标

1. **召回准确率**：A/B 档诗人代表诗在相关热点的候选池 Top200 中占比 ≥80%
2. **语义覆盖**：15 类主题标签覆盖主流热点，不再依赖标题字面匹配
3. **金句识别**：标志性诗句（"但愿人长久""长风破浪会有时"等）独立作为检索 key
4. **散篇合并**：同一 poem 的多版本 content 在 term 层合并，不产生双倍噪音
5. **可演进**：标签体系可增量扩展，不因 ETL 重来

## 四、方案设计（三层 ETL）

### 4.1 新增表：`poem_tags`（主题标签层）

```sql
CREATE TABLE poem_tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    poem_id INTEGER NOT NULL,
    tag VARCHAR(32) NOT NULL,
    tag_type VARCHAR(16) NOT NULL DEFAULT 'theme',  -- theme/style/emotion/scene/golden
    confidence INTEGER NOT NULL DEFAULT 100,        -- 0-100，人工标注100，AI推断<100
    source VARCHAR(32) NOT NULL,                    -- manual/ai_infer/golden_rule
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_poem_tags_tag ON poem_tags(tag);
CREATE INDEX idx_poem_tags_poem ON poem_tags(poem_id);
CREATE INDEX idx_poem_tags_type ON poem_tags(tag_type);
```

**标签体系（15 类 × 30-80 个 tag）**：

| tag_type | 示例 tags | 来源 |
|---------|----------|------|
| `theme` | 豪放/婉约/田园/边塞/思乡/怀古/咏史/爱情/送别/隐逸/哲理/忧国忧民/壮志难酬/羁旅/宫怨/咏物 | 基于诗人流派+内容关键词规则 |
| `style` | 仙气/剑仙/浪漫/悲壮/清丽/雄浑/沉郁/空灵/旷达/细腻 | 基于 AI 小模型分类 |
| `emotion` | 悲秋/喜悦/离愁/思乡/孤独/豪迈/闲适/愤懑/惆怅/欢快 | 基于关键词+句式 |
| `scene` | 山水/田园/月夜/秋景/春景/冬雪/边塞/宫廷/江湖/山水画卷 | 基于场景词 |
| `golden` | （金句级）明月几时有/长风破浪会有时/但愿人长久/床前明月光 | 基于经典名句库 |

### 4.2 新字段：`poems.golden_lines`（金句标记层）

```sql
ALTER TABLE poems ADD COLUMN golden_lines TEXT;  -- JSON array of golden sentence strings
-- 例: ["明月几时有，把酒问青天", "但愿人长久，千里共婵娟"]
```

金句规则（`scripts/build_golden_lines.py`）：
- 基于 S/A 档诗人代表作，人工标注其标志性诗句
- 金句作为独立的检索 key 写入 `poem_terms`（带特殊 position='g'）
- 倒排查询时，golden 命中额外加分（而非直接替代 hits）

### 4.3 新字段：`poems.content_hash`（散篇合并层）

```sql
ALTER TABLE poems ADD COLUMN content_hash VARCHAR(64);  -- SHA256(content)
-- 建立唯一索引防止完全重复 content 的多条记录
CREATE UNIQUE INDEX idx_poems_content_hash ON poems(content_hash) WHERE content_hash IS NOT NULL;
```

合并策略：
- ETL 运行时，相同 `content_hash` 的多条 poem → 保留 fame_score 最高的那条（或最早录入的那条）
- 其余 poem_id 的 poem_terms 合并到保留者
- 原 poem 标记 `is_merged BOOLEAN DEFAULT FALSE`

### 4.4 新脚本：`scripts/build_poem_tags.py`

```python
"""
阶段1：基于规则批量打标签（无需 AI API）
- 朝代 + 作者流派 → theme 标签（李白→豪放/浪漫，杜甫→忧国忧民/现实）
- 标题/内容关键词 → scene/emotion 标签
- S/A 档诗人代表作 → golden 金句（从 poem_terms 中按长度+频次启发）

阶段2（可选）：AI 小模型补充 style 标签
- 使用本地 small LLM 对 poem content 做风格分类
- 写入 poem_tags（confidence < 100，可后续人工校准）
"""
```

### 4.5 修改 `build_terms_index.py`

- 新增 `--with-tags` 参数：构建时同时读 `poem_tags` 并写入 `poem_terms`
- 新增 `position='g'` 表示金句 term（在 `_rule_candidates` 中额外加权）
- 停用词过滤：移除 >10 万首诗命中的 term（全局停用词表）

## 五、改造 `_rule_candidates`（查询侧）

```python
async def _rule_candidates(self, db, keywords, limit=200):
    # 1. 倒排 term 召回（现有逻辑）
    primary_ids = await self._primary_retrieve(db, keywords)
    
    # 2. 名望兜底（已有 C 实现）
    fame_ids = await self._fame_fallback(db)
    
    # 3. 标签召回（新）：用 poem_tags 查 tag IN keywords
    tag_ids = await self._tag_retrieve(db, keywords)
    
    # 4. 合并去重，按 hits（term 数）+ tag_hits + fame_bonus 排序
    merged = await self._merge_candidates(db, primary_ids, tag_ids, fame_ids)
    return merged[:limit]
```

排序权重（新）：
```
score = hits * 1.0 + tag_hits * 1.5 + golden_hits * 3.0 + fame_bonus
```
- `golden_hits` 金句命中额外加 3 倍分（确保"明月几时有"类金句诗必进候选）
- `tag_hits` 主题标签命中加权 1.5 倍（比纯分词 term 更有语义）

## 八、用户质疑逐条回应 + 推荐架构（v2.1 调研版）

### 8.1 "数据源太大 → 推荐计算丢失"：成立，机制是三层漏斗

代码实测（`recommend_poems`, hotspot.py:689）：`203 万首 → 检索词命中 → _rule_candidates 截断 Top300（倒排200 + 名望兜底100）→ LLM/规则选 3`。

丢失发生在两处，且被 §2.2 的数据形态**放大**：
1. **召回侧（真丢失）**：检索词与名诗 terms 错位即 hits=0，名诗根本进不了 300。→ 靠"语义召回路"补（§8.4）。
2. **漏斗侧（结构失真）**：同题组诗拆条 86.9 万行让候选池被同质/同题条目挤占、名诗各子条 hits 被摊薄（《秋兴八首》8 条各自 hits≤1，而一条当代打油诗 hits=2 就能压过）。→ 靠"组诗归并为作品单元"直接减压（候选池的行空间缩至 ~120 万单元级，名诗聚合分恢复）。

### 8.2 "jieba 分词不是语义检索，标签/停用词治标不治本"：同意，但落地需分层

业界共识（ACP-RAG, NAACL 2025；向量化古诗词库工业实践）：**语义向量路与关键词倒排路互补，不是替代**——语义抓"意象/整体意境"，关键词抓"文化符号/固定表达"。且 38 万句向量化的实践强调 **分层配额采样**（防唐诗因语料量大过度代表），与本库"苏辛李杜被 203 万首淹没"同构。

**但全量 203 万首向量化成本高、收益低**（绝大多数是非推荐目标的冷门/低质条目）。建议**语义只作用于"精选作品层"**（归并后 S/A/B 档 + 权威选本 ≈ 数万级），全量仍走词面倒排兜底。

### 8.3 "金句/核心点/季节"：三类诉求，三种工程强度

| 诉求 | 本质 | 建议做法 | 强度 |
|------|------|---------|------|
| **季节/节令** | 确定性可全覆盖 | 季节意象词表（梅/雪/冬、荷/蝉/夏、雁/秋风/霜…）+ 节令/节气词（中秋/重阳/清明）+ 标题规则。**规则词表先行，全量可跑、可断言验收** | 低（规则） |
| **金句** | 注入问题非识别问题（§2.3） | 金句库（选本名句，千条级）按标点断句 → 整句写入 `poem_terms position='g'`；golden_hits 加权 | 中（词库+断句） |
| **核心点（爱国/忠君/忧国忧民）** | 主观主题，需先验锚定 | ① 先验锚：作者流派/代表作人工标注（复用 fame ETL 的 238 人表思路，给"忧国忧民型"代表作打 tag）；② 意象规则：庙堂/家国词（社稷/君王/戎马/关山…）；③ 可选：仅对精选层做离线 LLM/分类器打标（confidence<100） | 高（先验表 + 规则；AI 可选） |

**优先级主张**：季节与组诗合并是**确定性最高、可验证性最强**的第一步；金句次之；核心点主题标签最后（先验词表先行，AI 延后）。

### 8.4 推荐架构（修订版）

```
候选池 = 词面倒排召回(去重后全量)          # 已有，可保留
       ∪ 主题标签召回(poem_tags: season/theme/style)
       ∪ 金句召回(position='g' 整句命中)
       ∪ 名望兜底(已有 C 实现)
       ∪ [P2 可选] 精选层语义召回(向量, 仅数万级)
排序 = hits*1.0 + tag_hits*1.5 + golden_hits*3.0 + fame_bonus   # 沿用 §五
```

**语料分层（合并后）**：
- L1 名篇金句层：权威选本/名望 S/A 档代表作 + 金句（万级）——**召回与 LLM 双保底**
- L2 主题标签层：季节/流派/核心点标签（数万~数十万级）
- L3 全量词面层：其余全部（词面检索仍能捞到小众/长尾）

## 九、抖音传播形态调研 + 精选层双通道（v2.2）

### 9.2 两个案例作者的库内实测（回应"近代精品被误杀"）

| 作者 | 库内处境 | 问题 |
|------|---------|------|
| 仓央嘉措 | poets 1 条：朝代=清、fame=14.0（E 档）、cat=normal；poems 30 首（曾缄式七言翻译《情诗其一/其九…》32 字/首） | 无选本/课本收录 → fame 仅 14。若精选层门槛设为 fame≥B，**他被整体误杀**。而他恰是短视频第一梯队传播符号（情歌/禅意/西藏符号）。 |
| 张渠（用户例） | poems/poets 均 0 首 | 若指作曲家张渠（舞剧《李白》《孔子》《昭君出塞》作曲、徐志摩诗剧《何以相逢》）→ 说明**大量"诗词×音乐演绎"素材根本不在文本库**，它们靠配乐出圈；若指南宋词人张渠（《青玉案·被檄出郊》曾入选教辅赏析）→ 冷门但真实，词面层能兜住。**待用户确认所指。** |

**关键认知**（写进设计的根本假设）：传播热 ≠ 古典名望。`fame_score` 度量"被历史/教材选择"，抖音热度度量"被当下情绪选择"。两者交集大（李白两榜都第一）但**并集更大**——仓央嘉措（fame 14 / 传播顶级）就是反例。精选层必须**双通道**，不能只认名望。

### 9.3 精选层入选双通道（v2.2 核心修订）

```
通道 1 · 古典名望（确定性规则，免费）  通道 2 · 传播共鸣（精选先验表，人工 curated）
  fame≥B 档（S/A/B 51 人）          +    传播热度锚（抖音/音乐/影视反复使用：
  权威选本（唐诗三百/宋词三百）               仓央嘉措情歌、纳兰词、被翻唱古诗词…）
  课本收录（textbook_hits>0）                真实归属可考的现代精品（张枣《镜中》等）
```

- 通道 2 维护成一张小表 `viral_anchors`（百条级），每行：`anchor_name(传播署名,如"仓央嘉措") / real_author(真实归属,如"曾缄译/扎西拉姆·多多") / work_ids / 传播场景标签(情歌/禅意/西藏) / confidence`。
- **入选后仍走同一套 poem_tags 打标 + core_idea 标注**，只是"入场券"不同。
- **伪托不是要删的脏数据，而是要修的归属错位**（反杜撰纪律的延伸）：库内《情诗其一》真实署名应为"曾缄译仓央嘉措诗"，展示时可用"仓央嘉措"传播署名 + 备注译者，但**不得把现代伪托（《见与不见》=扎西拉姆·多多）标成仓央嘉措原作**——宁可不归、不可错归。

### 9.4 每诗"核心思想"一句话标注（poem.core_idea）——用户："有了这个很多问题就解决了"

| 用途 | 机制 |
|------|------|
| 热点→诗 的语义桥 | 热点标题与 core_idea 做语义匹配（embedding 或关键词），跨词面召回——"古风火了"不再需要命中"仙气"字面 |
| 校验层 | 金句/标签/内容三方对齐（core_idea 说"思乡"，金句与 scene 标签应能佐证），防 AI 打标幻觉 |
| LLM 精选的输入 | 把 core_idea 喂给 LLM 让其在候选池内选"主旨最贴热点"的 |

- 范围：**只标精选层**（双通道入选 ≈ 数万首，批量 LLM 20–50 首/请求可覆盖）。
- 字段：`poems.core_idea TEXT`（一句 20 字内现代白话）+ 可选 `core_idea_embedding`（仅对精选层生成，P3）。
- 纪律：core_idea 由 LLM 生成后**规则抽验**（句内必须含 content 中可回查的核心意象词，防杜撰——复用 quotation-extraction-system 的自验证思想）。

### 9.5 时间线维度（poet/poem 系年）

- 三层：`poets.birth_year/death_year`（S/A/B + 通道2 锚，百科级人工或规则抽）→ `poems.work_year`（仅确有系年考据的，如《水调歌头》1076 丙辰中秋）→ `poems.period_tag`（早年/中年/贬谪期/暮年，粗粒度先验）。
- 触发场景：节令（中秋自动关联丙辰中秋）、历史/文化事件纪念（长安三万里效应 = 作品系年 + 人物传记事件）、人生阶段匹配（"职场失意"→ 苏轼黄州期）。**节奏：P1 只做诗人级时间线 + period_tag 粗标，作品级系年延后。**

### 9.6 200 万全量的定位（回应"200w 数据是基础"）

全量不是推荐负担，是**三条基础设施**：
1. **校验源**：金句/core_idea 回查、归属纠错（伪托识别靠 content 检索）的语料底。
2. **归并源**：同题组诗拆条的合并必须基于全量（§2.2），合并后行空间 ~120 万单元级。
3. **词面兜底层 L3**：长尾/小众/应试冷门仍可被词面检索捞到（§8.4 分层）。合并、去重、打标都**不删原始行**，只加"作品单元/标签/校验标记"列，保持可回溯。

### 9.7 v2.2 新增待决策

1. **"张渠"所指**：作曲家（舞剧配乐出圈 → 需为推荐结果关联"演绎/配乐"素材源？）还是南宋词人（库内冷门词面兜底）？——决定要不要引入"演绎作品"数据通道。

## 十、"一首诗是否有意义"判定架构定稿 + LLM 评分规则（v2.3）

> 触发与拍板（2026-09-03）：用户定义「有意义 = 主流/网络/媒体认可度 + LLM 基于提示词与诗本身特征、按评分规则判定」；要求先总结"流行的规律与受众"再定 LLM 规矩，使其与外部认可度高度重合；接受"漏掉没办法——有人喜欢就总有人不喜欢"。
> 结论前置：**两维度不做并列加权打分，采用「顺序闸门 + 分工」**；LLM rubric 复刻爆款配方而非文学批评标准。

### 10.1 为什么是"顺序闸门"而不是"加权综合"

| 维度 | 信息属性 | 证据强度 | 覆盖范围 | 典型误差 |
|---|---|---|---|---|
| ① 认可度（主流/网络/媒体） | 外部验证（后验） | 强——已被历史/媒体/人群筛过 | 窄——只覆盖"已被传播的" | 漏掉未被发掘的精品 |
| ② LLM 评分（提示词×特征×rubric） | 内部评估（先验） | 弱——无外部证据，可能自嗨 | 全——任意一首都能评 | 高分但无共鸣，淹没精选层 |

若并列加权：张渠/仓央类"LLM 高分但外部尚未认证"会被名望门槛误杀（用户点名要保的）；LLM 高分打油诗反向稀释名作。顺序闸门让两者各司其职：

```
通道1 古典名望(fame≥B / 选本 / 课本) ─┐
                                      ├─→ 直接入层（保下限，宁可不归、不可错归）
通道2 viral_anchors 传播共鸣锚        ─┘
        ↓（未过闸门的长尾全量）
LLM rubric 初筛（只评空白区，控成本）
        → 高分进「待验证」
        → 传播信号 / 人工抽查背书 → 转正入层 + 回填通道2（闭环越用越准）
```

- 认可度 = 硬门槛（保下限）：主流文化认可 ≈ 通道1 古典名望；网络/媒体认可 ≈ 通道2 viral_anchors。代码里 `_rule_candidates` 的 C 兜底即雏形。
- LLM = 分工（补盲区 + 统一打标）：① 对未过闸长尾做意义初筛（只跑空白区）；② 对已入层诗词统一打 core_idea/意境/情感标签（既定 ETL 诉求，与初筛同批调用顺带完成，控成本）。
- **core_idea/主题标签 ≠ 意义判定**：两百万人写过"爱国/忠君"，主题只是分桶；意义 = 表达质量 × 共鸣度，由认可度 gate + LLM 质量分判定，标签只负责把入选诗组织起来供排序与内容生成。

### 10.2 传播规律实证（定 rubric 前的校准原料）

**受众三层画像**：

| 层级 | 画像 | 关键证据 |
|---|---|---|
| 核心 | 18–30 岁，用诗当"情绪嘴替" | 诗朗诵参与者 18–30 岁占 67% |
| 出圈 | 普通人 + 反差感 | 46 岁瑜伽教练对诗出圈；2026-07 邯郸 16 岁女生山顶喊"横渠四句"点赞超百万 |
| 场景 | 配图/签名/文案/BGM/作文引用 | 37% 的人把"伪诗"写进过作文 |

**爆款规律 → LLM 规矩的含义**：

| # | 规律 | 实证 | rubric 含义 |
|---|---|---|---|
| 1 | 情绪浓度 > 文学价值 | 2026 刷屏六首全是释怀/自愈/坚韧/遗憾；刘禹锡"沉舟侧畔"8 亿播放、李煜"一江春水向东流"单句 10 亿+ | 第一权重 = 能否击中一种当代普世情绪 |
| 2 | 金句可独立存活 | "但愿人长久/一蓑烟雨任平生/千磨万击还坚劲"单句脱离全诗反复被引用 | golden 层权重拉满；诗平庸但有一句可引即值钱 |
| 3 | 零认知成本 | 伪诗完读率是真诗 4 倍、互动 3–5 倍、单条 ~1000 万播放 vs 真诗创新 ~200 万 | 直给 > 含蓄，评分须含"认知成本"维度 |
| 4 | 国民级意象是流量入口 | 算法把"风雪/少年/相思/月"归为高情绪价值内容 | 意象标签（月/雪/山河/桃花）本身带传播势能 |
| 5 | "伪诗"是反面教材 | "无人扶我青云志"标徐霞客、实为 AI 生成，触达 2 亿 | real_author 铁律：学其情绪配方、绝不学其归属造假 |
| 6 | 场景绑定才破圈 | 横渠四句 ≠ 诗，靠山河场景爆火（山顶呼喊/长城吟诵） | 通道 2 锚表收录非诗引用文本 |

### 10.3 LLM rubric：六维评分卡（唯一"内部评估"标准）

职责声明：LLM 不是文学批评家，是"爆款配方复刻器"——给未过外部闸门的长尾打分，使高分项尽量与外部认可度重合。

| 维度 | 权重 | 对应外部信号 | 判分要点（提示词要求） |
|---|---|---|---|
| 情绪共鸣度 | 30% | 释怀/自愈/坚韧/遗憾破亿清单 | 能否匹配 ≥1 种当代普世情绪？浓度多高？ |
| 金句可引性 | 25% | 单句 10 亿播放现象 | 是否存在可独立引用、3 秒读完的一句？ |
| 意象画面感 | 15% | 风雪/少年/月/山河国民意象 | 是否有可视觉化、可出片的意象？ |
| 直给度（认知成本） | 15% | 伪诗完读率 4× | 是否短、明、无需注释？含蓄是否过度？ |
| 语言凝练度 | 10% | 对仗工整短句式易记忆 | 节奏、音韵是否可记忆？ |
| 主题普适度 | 5% | 家国/爱情/乡愁共鸣广度 | 是否只写私人琐事？（课儿联类降权） |

两条铁律：
- **伪托零容忍**：无 real_author 或归属存疑 → 直接不入层（宁可不归、不可错归）。
- **伪诗体质降权**：情绪直给但意境空泛、意象拼贴无文化锚点（"踏雪至山巅"式）→ 总分 ×0.6——它有传播力但没有"有意义"的文化内核。

校准方法（比纯文字描述收敛快）：**few-shot 标杆**——
- 正样本（8–10 分示范）：沉舟侧畔千帆过 / 一江春水向东流 / 但愿人长久 / 一蓑烟雨任平生 / 天生我材必有用……让 LLM"先见过爆款长什么样"；
- 负样本（4–5 分示范 + 逐维扣分理由）：库内当代打油诗（中秋月饼类）与伪诗体质拼贴句；
- 输出要求：每维一行加分/扣分理由（可审计，防"总分行但说不出为什么"）。

与成片文案层评审（critic.py `CRITIC_SYSTEM_PROMPT`：共情 30/节奏 20/钩子 25/史实 15/原创 10）的分工：本 rubric 管"选哪首诗值得做片"（**选诗意义层**）；critic 管"这首诗的成片文案好不好"（**文案质量层**）。同一首诗若文案层反复不达标 → 反向提示选诗层"该诗可叙事性差"——双层反馈闭环（详见 docs/design/2026-09-03-video-communication-design.md）。

### 10.4 闭环与容错

- LLM 高分长尾进「待验证」→ 命中传播信号（外部热词/被引用上升）/ 人工抽查 → 转正入层 + 回填 viral_anchors 与 poem_tags（confidence<100）→ 锚表越用越准。
- 漏掉是可接受的：认可度闸门只覆盖"已传播的"，LLM 再准也有死角；漏掉的精品某天被热点带火，自然获得外部认可度进入通道 2——闭环兜底，不追求当下 100% 捕获（用户："有人喜欢就总有人不喜欢"）。
